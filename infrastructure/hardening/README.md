**WCS CIMS data is excluded from Borg (7 October 2026).** George approved "exclude and purge" for Women's Community Shelters CIMS client data and credentials. `CIMS_EXCLUDE_PATTERNS` in `onestack-backup.py` is the authoritative control: Borg-native `pp:` entries for the literal paths (`/opt/cims-export-worker`, `/etc/cims-export-worker`, `/var/lib/onestack-cims`, `/var/log/cims-export-worker.log`) plus `sh:**/` forms that also catch staged copies, renamed copies and rotated logs, data, exports and `.dev.vars*` in any `cims-export-worker` checkout, and `wcs-curate-*` and `wcs-cims-*` working folders. They are passed to every `borg create` even if the live config lacks them; the SQLite snapshot's skip of the runner directories is defence in depth. The runner's unit files, drop-ins and logrotate file stay in the backup. Purging existing archives, compaction (with `--threshold 0`), verification, retention and the VPS wipe after the runner moves to Australia are in [the purge plan](reports/wcs-cims-backup-purge-2026-10-07.md). `tests/test_cims_backup_exclusions.py` runs the script's exact `borg create` command and the plan's exclusion file against a disposable repository and keeps the script, `config/backup.example.json` and the plan in step.

The backup runs as root over container- and guest-writable trees and never follows symlinks there. Below a Docker mount root, Python works only through descriptors: `os.fwalk` without following links, files opened relative to their directory descriptor with `O_NOFOLLOW`, and no path check followed by a later use. SQLite still opens databases by name, so after each SQLite copy every file the connection opened must be the inode found by the walk or its sidecars; otherwise the copy is deleted and the run fails. SQLite itself refuses symlinked `-wal` and `-shm` files. The guest filesystem is a read-only mount of a completed copy, mounted `ro,noload,nosuid,nodev,noexec`; guest paths must resolve inside it, and rsync does not recreate guest device nodes or FIFOs. Borg stores symlinks as links and is never run with `--read-special`.

The off-host Worker checks heartbeat, backup age/failure, disk, expected containers, host units, both guest roles and Tailscale. Private Telegram alerts report meaningful changes. Restore `/etc/onestack-monitor/config.json` and `expected-services.json`; update the inventory after intentional additions/retirements.
